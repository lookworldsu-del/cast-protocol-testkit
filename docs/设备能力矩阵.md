## 能力判定

每项能力分别记录“资料依据”和“实测状态”：

- 资料依据：产品明确声明 / 官方资料未说明 / 方案待确认，并附来源、适用型号和查阅日期。
- 实测状态：待验证 / 已验证支持 / 已验证不支持 / 条件支持 / 无法确认；除“待验证”外均须附证据、适用条件或无法确认的原因。
- 用例适用性：资料与实验条件确认后，标记适用、不适用或阻塞；未知能力不能直接算不适用。

## 每个接收方案需确认的项目

| 能力 | 需记录的条件 |
| --- | --- |
| AirPlay 媒体输出与镜像 | 两种模式分别确认；接收软件、开关、认证/配对、访问策略、系统版本 |
| 点对点 AirPlay | 源与接收端的具体支持条件；不得从 Apple TV 的能力推断第三方投影仪 |
| DLNA / UPnP AV | 设备/服务描述、版本、AVTransport/RenderingControl 动作、媒体能力及差异 |
| Miracast | 手机系统和接收端是否均支持；实际入口、连接模式、分辨率与内容保护条件 |
| Google Cast | 目标型号是否支持、接收实现和版本；是否需提高后续开发优先级 |
| 媒体与内容保护 | 编码、封装、码率、音轨、字幕等能力；内容输出策略与保护链路 |
| 诊断采集 | 可用 App 日志、系统诊断、ADB、接收端日志和外部抓包条件 |
| 网络并发 | 基础设施 Wi-Fi、P2P、热点、互联网依赖、隔离/转发策略与无线并发限制 |

## 每次实验的环境记录

需包含拓扑图或文字路径、设备有线/无线接入方式、AP 型号与配置、频段/信道、测试位置、网络可达性和干扰条件；网络扰动实验另记作用位置及流量确实经过的证据。

媒体清单记录素材 ID、来源/使用条件、生成方式、校验值、时长、封装、视频编码及参数、音轨、字幕、URI 和内容源位置。先从少量可复现素材开始，不将 4K/H.265 等格式直接等同于设备应支持。

若以软件接收端或电视代替投影仪，报告中应写明替代关系及覆盖限制；软件互通结果不直接外推为投影仪整机体验结果。

## 目标产品范围的资料线索

查阅日期：2026-11-06。以下仅为产品资料线索，尚未在本项目验证：

资料可能随型号、地区与版本变化。引入实际设备后，应重新核对官方说明与真实能力；不据上述资料推断全系列支持 DLNA 或 Miracast。
