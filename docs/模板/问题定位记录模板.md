# 问题定位记录模板

[返回项目首页](../../README.md) · [排查框架](../投屏问题排查框架.md)

> 空白模板，未记录任何已发现或已修复的产品缺陷。故障注入实验应标记为“实验”，不能作为真实产品缺陷发布。

## 基本信息与复现

| 字段 | 记录 |
| --- | --- |
| 问题编号 / 类型 | 待填写；产品缺陷候选 / 实验故障注入 / 环境问题 / 能力待确认 |
| 关联 run_id / case_id / attempt_id | 待填写 |
| 协议、模式与内容源位置 | 待填写 |
| 发送端、接收端、固件与接收 App | 待填写 |
| 媒体 ID / 校验值 / URI 类型 | 待填写 |
| 网络拓扑、前置条件与复现步骤 | 待填写 |
| 预期依据与实际表现 | 待填写 |
| 复现次数 / 总尝试数 / 用户影响 | 待填写 |

## 观察与排除

| 阶段 | 已观察事实 | 原始证据位置 | 尚不能证明什么 |
| --- | --- | --- | --- |
| 网络可达与发现 | 待填写 | 待填写 | 待填写 |
| 控制/会话与协商 | 待填写 | 待填写 | 待填写 |
| 媒体访问与解码 | 待填写 | 待填写 | 待填写 |
| 实际画面、音频与恢复 | 待填写 | 待填写 | 待填写 |

## 原因假设与验证

| 假设 | 验证实验与控制变量 | 结果和证据 | 支持/排除/待验证 |
| --- | --- | --- | --- |
| 待填写 | 待填写 | 未执行 | 待验证 |

结论分开填写：已证实原因、当前最可能原因、无法确认的阶段、需要接收端/固件团队提供的额外观测点。不要将“最后能看到的正常事件”当作故障必然发生的位置。

## 处理与回归

- 修复、配置调整或实验恢复动作：待填写。
- 归属建议及依据；需协作的角色：待填写。
- 回归版本、相同条件复测、邻近风险场景及结果：待填写。
- 是否仍需重启、残留状态、异常恢复能力：待填写。
- 对发布风险的影响与未消除风险：待填写。
- 最终状态：待定位 / 已定位待处理 / 待回归 / 已验证关闭 / 能力或需求待确认。
