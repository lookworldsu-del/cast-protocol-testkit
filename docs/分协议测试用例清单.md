# 分协议测试用例清单

更新日期：2026-11-06。当前为用例设计稿，27 条用例均为 `NOT_RUN`，没有代码、已确认设备或实测结果。

本页是执行计划入口。执行前填写 [设备能力矩阵](设备能力矩阵.md)，固定预期与参数；测量遵循 [指标测量方法](指标测量方法.md)，结果使用 [测试报告模板](模板/测试报告模板.md)。范围与优先级原则见 [测试策略](测试策略.md)，协议角色见 [协议原理对比](协议原理对比.md)。

结果统一为 `PASS / FAIL / BLOCKED / NOT_RUN / NOT_APPLICABLE`；人工、自动、混合是独立的执行方式字段。下列“方式”均为未来方案，未表示已完成自动化。能力未知或缺少判定条件时先补齐条件，不能将其算作通过；确认不适用须记录依据。

每次保留 `run_id`、用例版本、设备/固件/接收软件版本、网络拓扑、媒体标识、参数、操作与观察时间线。P0 为已支持场景的核心使用及失败后恢复，P1 为常见体验与兼容风险，P2 为扩展组合；可按目标用户场景调整并记录理由。各用例未注明的数值阈值均待确定。

## 一、DLNA / UPnP AV：10 条

共同条件：明确控制器、媒体服务器、渲染器角色；媒体 URI 必须从接收端可达。分别记录 SSDP 发现、描述获取、SOAP 响应、HTTP 取流与实际出画，任何单一步骤成功均不等于播放成功。

### DLNA-001｜P0｜设备发现

- 条件与操作：接收服务开启；分别以冷启动、已有缓存状态发起搜索。
- 预期与证据：发现目标唯一设备并能关联描述地址；保存搜索/响应时间线、设备标识和重复项。计时终点及目标值执行前确定。
- 方式：混合，规划由程序记录发现事件，人工核对目标设备。

### DLNA-002｜P0｜描述与能力探测

- 条件与操作：已取得设备描述地址；解析服务列表，查询可用的媒体/传输能力。
- 预期与证据：记录设备实际声明的服务和动作；不支持的能力明确呈现，不因缺少可选动作判整个协议失败。保存描述、能力响应或错误。
- 方式：自动，规划覆盖解析与能力记录。

### DLNA-003｜P0｜外部 HTTP 源正常播放

- 条件与操作：选择双方声明支持的非保护素材；设置外部媒体 URI 并开始播放。
- 预期与证据：控制请求与响应可关联，接收端实际出画/出声并持续播放；保存媒体 GET、状态记录和画面证据。
- 方式：混合，规划自动发指令与采集，人工或外部设备确认出画。

### DLNA-004｜P0｜手机提供本地媒体

- 条件与操作：手机运行本地 HTTP 服务；使用接收端可访问的地址播放同一素材。
- 预期与证据：接收端从手机服务取流并实际播放；保留请求来源、URL、响应和画面，禁止以控制器本机可访问代替接收端可访问。
- 方式：混合，服务与控制记录自动，画面确认按设备条件执行。

### DLNA-005｜P1｜暂停与继续

- 条件与操作：已确认相关动作可用；播放中暂停，再继续。
- 预期与证据：实际画面与播放状态符合预先确定的暂停/继续语义；分别记录 SOAP 响应和可见效果时间，不把响应时延当画面响应时延。
- 方式：混合；动作不可用时按能力依据标不适用。

### DLNA-006｜P1｜Seek 与位置查询

- 条件与操作：媒体可寻址且设备支持相应模式；跳转到预定位置并查询进度。
- 预期与证据：结果符合支持的精度和误差要求；保存目标位置、返回位置、HTTP Range 行为及画面证据。不支持的模式应有可解释响应。
- 方式：混合，位置查询与指令可自动，实际效果另行确认。

### DLNA-007｜P0｜停止与再次播放

- 条件与操作：播放中发送停止，再设置媒体并播放。
- 预期与证据：停止与再播均符合接收端约定状态，过程无需重启恢复；保存状态序列、取流记录与画面。停止不强制等价于退出接收 App。
- 方式：混合，规划循环控制与结果采集。

### DLNA-008｜P0｜媒体请求失败后的恢复

- 条件与操作：可控 HTTP 服务先返回预定错误（如 404），再更换为有效 URI 重试。
- 预期与证据：失败可被识别、不会报告实际播放成功；恢复后可播放有效媒体。保存控制结果、HTTP 状态、超时与恢复画面。
- 方式：混合，故障注入与指令自动，物理结果另行判定。

### DLNA-009｜P1｜手机断网与退出的源位置差异

- 条件与操作：分别使用外部服务、手机本地服务；播放中断开手机网络或终止服务，独立执行各组合。
- 预期与证据：按实际媒体路径、缓存和会话策略确定行为；外部源不预设必然续播，本地源不预设立刻停播。记录服务存活、取流停止和播放变化。
- 方式：混合，人工扰动，规划关联媒体请求与播放观察。

### DLNA-010｜P1｜接收服务重启与发现信息恢复

- 条件与操作：接收端服务重启，必要时变更名称后重新发现、播放。
- 预期与证据：旧信息按声明的有效期或刷新策略处理，重启后可重新使用；记录通知、缓存、描述与重连结果，不要求名称零延迟刷新。
- 方式：混合，重启依权限人工或自动，发现与控制记录自动。

## 二、AirPlay：9 条

共同条件：分别确认媒体外部播放与系统屏幕镜像是否受支持。系统路由选择、控制中心镜像保留人工步骤；公开 API 事件不等于完整握手信令，外部播放激活也不等于接收端出画。

### AP-001｜P0｜媒体路由选择与播放

- 条件与操作：接收端开启相应能力；App 播放受支持素材，经系统媒体路由选择目标。
- 预期与证据：目标正确、实际播放成功；记录操作视频、可获得的路由/播放器事件和接收画面。独立观察设备选择成功与播放成功。
- 方式：混合，人工选择，规划自动记录公开事件。

### AP-002｜P1｜媒体参数兼容

- 条件与操作：按能力选择不同编码、封装、分辨率和码率，逐项切换受控素材。
- 预期与证据：声明支持的组合正常播放；不支持项按产品约定处理。保存媒体元信息、错误及画面，不因文件标称 4K 推定接收输出为 4K。
- 方式：混合，素材切换与事件记录可自动。

### AP-003｜P1｜媒体播放控制

- 条件与操作：外部播放已建立；依次暂停、继续及执行受支持的 Seek。
- 预期与证据：接收端可见行为与控制语义一致，位置误差满足预定要求；保存操作、播放器状态与接收效果。
- 方式：混合，规划自动执行 App 内控制，另行核对接收画面。

### AP-004｜P0｜系统镜像建立

- 条件与操作：确认镜像支持；从控制中心选择目标，显示编号和动态测试画面。
- 预期与证据：目标接收端出现持续更新的正确画面；保留系统选择流程及两屏视频。不能仅凭 App 的外部播放状态判镜像结果。
- 方式：人工或混合；规划关联运行编号与视频证据。

### AP-005｜P1｜旋转、锁屏与后台策略

- 条件与操作：媒体播放、镜像分别执行旋转、锁屏、切后台，每个组合独立记录。
- 预期与证据：按已确认的系统及产品策略判断保持、暂停或结束，恢复操作后状态一致；保存源端操作、两端画面及公开事件。
- 方式：混合；策略不明确时先补齐预期。

### AP-006｜P0｜主动结束与重新使用

- 条件与操作：分别结束外部播放、停止系统镜像，再建立同类会话。
- 预期与证据：状态按约定复位，再次使用无需异常重启；记录停止流程、残留画面与重连结果。
- 方式：混合，系统镜像操作先人工完成。

### AP-007｜P0｜网络中断后恢复

- 条件与操作：确认实际会话路径；对经过的网络实施可控中断，恢复网络后按既定流程重连。
- 预期与证据：异常状态可识别，恢复后可重新使用；是否自动恢复须预先约定。保存扰动有效性、状态变化和实际出画时间。
- 方式：混合；点对点路径不能用无关路由器扰动代替。

### AP-008｜P1｜内容保护策略

- 条件与操作：具备可合法使用的保护测试内容，明确接收能力和预期输出策略后执行。
- 预期与证据：按内容及链路保护策略判定允许输出或受限输出；黑屏本身不等于缺陷。保存策略依据、错误信息和接收表现。
- 方式：人工或混合；缺少内容、能力或观察条件则阻塞。

### AP-009｜P1｜持续播放与镜像稳定性

- 条件与操作：分别运行约定时长，记录中断、卡顿、画面停滞、发热相关事件及恢复。
- 预期与证据：按预设容忍范围判定；保留真实开始/结束时间和异常证据，配置时长不能当作已完成时长。
- 方式：混合，规划事件采集结合外部画面观察。

## 三、Miracast：8 条

共同条件：使用已确认支持 Miracast 的发送与接收设备，通过系统提供的投屏功能执行；普通 App 提供测试画面和记录辅助，Wi-Fi P2P 组网成功不能代替 Miracast 建立成功。

### MC-001｜P0｜系统投屏建立

- 条件与操作：接收端准备就绪；经系统入口选择设备，显示动态测试画面。
- 预期与证据：正确接收端出现持续更新画面及可用音频；保存系统步骤、两屏视频和权限允许的系统日志。
- 方式：混合，人工建立，规划关联采集。

### MC-002｜P1｜旋转与显示适配

- 条件与操作：显示比例、边框和清晰度图，切换横竖屏及已支持的显示模式。
- 预期与证据：符合模式要求，无异常拉伸、裁切或画面残留；记录源/接收画面与可取得的协商信息，不能由输入素材推定协商分辨率。
- 方式：人工或混合。

### MC-003｜P1｜锁屏与应用切换

- 条件与操作：镜像期间切换应用、锁屏，再解锁返回。
- 预期与证据：遵循系统与产品策略，返回后可继续使用或按约定重连；记录两端状态，不预设锁屏必然立即断开。
- 方式：混合，人工操作结合日志/视频。

### MC-004｜P1｜镜像端到端延迟

- 条件与操作：使用动态帧号；同一相机同时拍摄源屏与投影画面，多次采样。
- 预期与证据：按约定延迟目标与误差判定，未设目标则仅报告基线；保留原视频、取样点、分布和异常样本。
- 方式：混合，规划视频辅助分析。

### MC-005｜P1｜音画同步

- 条件与操作：使用闪白/蜂鸣素材，固定拍摄及拾音位置，分别观察稳定与扰动场景。
- 预期与证据：记录偏移方向、数值、距离与误差，按事先约定目标判定；不把源素材误差计为接收问题。
- 方式：混合，外部录制与分析。

### MC-006｜P0｜主动断开与再连接

- 条件与操作：分别从发送端和接收端结束，再次连接，按计划重复。
- 预期与证据：两端可按正常流程再次使用，无需重启消除残留；保存重复次数、每轮结果和失败后的恢复动作。
- 方式：混合；系统操作自动化仅在验证过的机型上实施。

### MC-007｜P0｜实际链路中断与恢复

- 条件与操作：明确 P2P 或基础设施路径，施加有效的可控断链并恢复。
- 预期与证据：异常与断链可识别，按约定恢复流程可重连；记录扰动位置、有效性和两端状态。路由器丢包未影响 P2P 时不能声明完成弱网覆盖。
- 方式：混合，依设备条件执行扰动和采集。

### MC-008｜P1｜受保护内容输出

- 条件与操作：有合适内容及能力依据，核对发送/接收端 HDCP 和内容输出策略后测试。
- 预期与证据：输出或限制符合已确认策略，异常后普通内容仍可使用；保存策略、可获得的协商证据与普通内容对照结果。
- 方式：人工或混合，条件不足标阻塞。

## 执行产物与完成标准

每条执行记录必须关联步骤、结果及证据。完成规划不代表完成测试；用例覆盖范围、未执行项与风险结论按 [质量门禁](质量门禁.md) 汇总。后续增补受控弱网、更多格式/设备组合与压力次数时，另立参数组合记录，避免以“已测一条”推定所有组合已覆盖。
