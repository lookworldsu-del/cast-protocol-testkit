# 指标测量方法

更新日期：2026-11-06。当前仅定义测量方案，没有实测基线；所有体验阈值、样本规模和稳定性目标时长均待确定。

本页用于执行 [测试用例](分协议测试用例清单.md) 时统一计时与判定，产物写入 [测试报告](模板/测试报告模板.md)。先按 [设备能力矩阵](设备能力矩阵.md) 固定设备、固件、接收软件、模式、媒体与网络拓扑，按 [质量门禁](质量门禁.md) 评价证据是否充分。

## 1. 区分代理事件与真实体验

| 指标 | 起止与观察方法 | 不能代替的证据 |
| --- | --- | --- |
| 设备发现耗时 | 从明确的搜索动作到工具获得目标有效发现信息；冷搜索、缓存命中分组 | 系统选择器出现不等于目标已被发现；无法观察内部发现时，单列人工可见耗时 |
| 控制请求时延 | 同一控制器单调时钟下，请求发出至响应或超时 | SOAP 成功、播放器状态变化不等于投影画面已响应 |
| 首帧耗时 | 从约定操作事件到接收画面首次出现有效目标内容；优先同一视频记录起止 | HTTP GET、路由激活、播放器 ready/playing 只能作为链路代理事件 |
| 恢复耗时 | 从已验证的故障解除到约定的可用状态及实际画面恢复 | 单独收到“已连接”不能证明体验恢复；人工操作等待须另记 |

手动选择设备的时间是否计入首帧耗时，应事先写明。无法同时拍到操作与画面时，说明计时关联方法与误差，不混用不同起点的数据。

## 2. 镜像延迟与音画同步

镜像端到端延迟采用同一高速相机拍摄源屏和投影画面，两屏同时显示可识别的动态帧号或时间编码。对同一拍摄时刻读取两屏内容的差异，结合源画面更新节奏估计延迟；保留原始视频、分析取样点、方法及异常样本。该方法不需要直接相减两台设备的系统时间。

相机帧周期、两屏刷新、滚动快门、曝光、帧号生成与排队都会产生误差；相机标称高帧率不等于同等精度。记录相机实际录制参数与测量不确定性，不能把手机绘制帧率或本地播放器掉帧计数当作投影端帧率。

音画同步使用已核验同步关系的闪白/蜂鸣素材，录制接收画面与声音，报告声领先或声滞后以及偏移量。记录拾音距离、录制设备自身音画偏差和是否使用蓝牙音频；需要时校正声音传播与录制偏差，保留未校正原值。不把测试素材或录制链路偏差直接归因于投屏接收端。

## 3. 样本、成功率与稳定性

执行前约定重复次数、热身处理、超时、失败重试和异常样本规则。每个有效尝试保留单次数据；失败不能通过无限重试后仅保留成功结果消失。

- 成功率同时报告成功次数、有效尝试次数、失败与排除原因；如“30/30 次成功”仅描述这批样本，不保证所有环境永久成功。
- 用例覆盖率明确计划范围及分母，区分已执行、通过、阻塞、未执行和不适用；不能把不适用或未执行算作通过。
- 耗时可报告中位数、分位数和极值，但须给样本数及分位计算方法。样本很少时列原始数据，避免对尾部表现作过强结论。
- 长稳记录实际开始、结束、有效观察时长、中断、恢复及采集空白。分别统计断连、画面停滞、卡顿、音画偏移；无应用错误日志不足以证明无体验异常。

没有预先确定的要求时，可以完成数据采集并标记“基线已采集、合格性待评价”；不得仅凭数值看起来合理，将相关性能断言记为 `PASS`。业务用例结果与测量数据的可用性分别记录。

## 4. 验证扰动确实作用于被测路径

分别画出控制与媒体路径，并记录故障注入点。DLNA 控制器到接收端的 SOAP 路径与接收端到媒体源的 HTTP 路径可能不同；手机同时提供媒体时，断网效果也不同。HTTP 404、响应延迟或连接中断只覆盖相应服务路径，不等于整个无线链路的丢包或干扰。

Miracast 的 Wi-Fi Direct 流量可能绕过路由器；AirPlay 也需确认是否采用点对点路径。不能因为路由器配置了损伤就认为投屏媒体已受影响。保留拓扑、配置、作用接口、有效性证据与解除时间；无法证明有效性时，将该扰动覆盖标为未验证。

网络吞吐明确统计接口、方向、时间窗口及控制/媒体流量；平均值不能代表峰值，手机端流量不能代替接收端全部流量。环境参数和结果解释见 [协议原理对比](协议原理对比.md)。

## 5. 时间线关联与交付

单设备耗时优先使用单调时钟。跨设备日志以运行编号、用例编号、媒体标识及可关联事件串联；需要精确相减时必须说明同步方式、偏移和误差，不能直接相减手机与接收端的墙上时间。单向时延不能由未同步时钟得出。

每项数据交付原始记录、单位、起止定义、统计方法、样本数、排除项、误差与证据链接。阈值来源区分产品要求、协商目标及实测基线；本项目方案不代表企业内标或协议认证标准。
