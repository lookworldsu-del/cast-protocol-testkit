# 架构设计

[返回项目首页](../README.md)

**阶段：设计草案。本文描述拟建设的模块与契约，当前均未实现。**

## 总体职责

移动端提供协议操作与可控输入，Python 组织实验和证据，接收端与外部测量提供真实输出信息。各端通过统一的用例、运行和媒体标识关联；无法采集的阶段显式保留证据缺口。

| 层次 | 输入 | 计划职责 | 输出 |
| --- | --- | --- | --- |
| 用例与计划 | 设备能力、风险、媒体清单 | 选择适用用例、执行方式、前置条件与判定规则 | 本次执行计划 |
| iOS 测试端 | 媒体、动作、测试画面 | AirPlay 公开 API 操作与事件记录、人工镜像辅助 | 发送端事件与操作记录 |
| Android 测试端 | 目标设备、媒体 URI、动作 | DLNA 控制与协议记录、系统 Miracast 操作辅助 | 控制证据、测试画面与人工记录 |
| Python 自动化 | 执行计划、可用设备接口 | 编排、HTTP 媒体源、可控故障、超时管理、采集与汇总 | 运行记录和证据索引 |
| 接收端诊断 | 可用权限和设备适配 | 采集版本、网络、接收进程与可获得的解码/会话信息 | 接收侧事件；采集限制说明 |
| 外部测量 | 两屏帧号、视听素材 | 确认真实出画、镜像延迟和音画关系 | 录像与测量记录 |
| 报告与判断 | 上述证据及判定规则 | 汇总结果、覆盖、阻塞、未知和质量风险 | 报告及候选版本结论 |

## 三类数据路径

**DLNA 外部媒体源**：手机作为控制器向接收端发送媒体 URI；接收端从 PC/局域网 HTTP 服务获取媒体。控制请求、HTTP 获取和实际出画分别取证。

**DLNA 手机媒体源**：手机同时承担控制器和 HTTP 内容源。手机断网、系统后台限制或服务退出可能影响后续取流；缓存导致的短暂继续不等于源依赖消失。

**系统镜像**：手机系统到接收端形成镜像会话。App 提供测试画面，但无法因此获取完整系统协议内部事件。AirPlay、Miracast 及具体接收实现分别确认路径；不能将基础设施 Wi-Fi、P2P 和点对点能力混用。

## 第一条自动化链路

DLNA 优先形成：确认接收端能力 → 发现与描述解析 → 设置媒体 URI → 播放 → 采集控制/HTTP/画面证据 → 能力范围内执行控制动作 → 停止并清理 → 汇总报告。

Python 侧先提供外部 HTTP 媒体源和执行汇总。Android 的自动动作入口在开发时选择合适的测试接口；第一阶段不为系统路由选择或系统镜像承诺通用无人值守能力。人工步骤应进入运行记录，而不是被自动化统计隐藏。

## 统一记录契约（拟定）

| 字段 | 用途 |
| --- | --- |
| run_id / case_id / attempt_id | 标识一次运行、用例及单次尝试；关联前后恢复/回归 |
| protocol / mode / topology_id | 区分协议、媒体/镜像模式与实际路径 |
| source / receiver / firmware / receiver_app | 记录型号、系统构建号、固件及接收软件版本 |
| media_id / checksum / media_origin | 确认素材一致性及外部/手机内容源位置 |
| execution_mode | 自动、人工或混合，与结果字段独立 |
| result | PASS / FAIL / BLOCKED / NOT_RUN / NOT_APPLICABLE |
| event_source / event_name | 区分操作、公开 API、协议请求、接收端日志和物理测量 |
| local_monotonic_time / wall_time | 单机耗时与跨源关联时间；不直接用未对齐的跨设备时间相减 |
| evidence_refs / limitations | 原始证据位置、采集权限、遗漏与测量不确定性 |
| expected_basis | 产品要求、项目候选规则或基线；无依据则注明待定 |

同一次运行可含多个来源。无法给系统协议添加自定义 ID 时，用操作记录、采集区间和环境信息关联，并注明关联置信度，不能声称实现了端到端协议 trace。

## 可控媒体服务与故障注入

计划提供固定素材、请求日志和可选择的正常/错误响应；逐步加入 404、响应延迟、限速、连接中断与 Range 行为实验。每次运行记录故障位置、启停时刻、参数和影响范围。

HTTP 源注入只证明该媒体访问路径的行为，不等于模拟所有无线链路问题。后续若使用可控网关/接入点进行网络损伤实验，需证明被测流量经过该位置；P2P 流量可能绕过网关。

## 接收端可测性与演进

先建立只读诊断适配，按权限采集。若后续能与接收端/固件团队协作，建议协商会话标识、发现/协商失败原因、选定媒体参数、首帧事件、断开原因码及恢复状态等观测点。本文将这些标记为改造建议，不作为现有接收端能力。

首版保留用户易懂的根层 iOS、Android 和 docs 目录。Python 实现开始时再建立自动化与媒体服务目录；不提前创建空壳平台、Java 服务或无法运行的 CI 配置。
